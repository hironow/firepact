# 0010. Plain mode for non-Firestore DTOs

**Date:** 2026-06-05
**Status:** Accepted

## Context

firepact targets Firestore realtime documents (ADR 0001/0002): `firepact-gen`
generates only `@firestore_realtime` roots, and the extractor stamps
`x-firestore-*` so `datetime` becomes `Timestamp`. But a real backend (the rain
integration) also has plain **HTTP DTOs** (request/response/payload models) whose
`datetime` is an ISO **string** over the wire, not a Firestore `Timestamp`. Those
were still generated by the legacy `pydantic-to-typescript`, which also drags in a
hidden system dependency on the `json2ts` binary.

To let a project drop the legacy tool entirely, firepact must also emit plain
DTOs (datetime -> string), not only Firestore documents.

## Decision

Add a **plain mode**: `firepact-gen --plain --module pkg.dtos` (native
`emit_plain` / `firepact emit --plain`). It builds the bundle with the **standard**
`GenerateJsonSchema` (no `x-firestore-*` stamping, so `datetime` -> `{string,
date-time}`), collects **every** Pydantic model defined in the module (not just
realtime roots), and emits **one plain interface per model** with declared
optionality, strict enums (no open union), and no read/write split / converter /
path helper.

This is NOT a general multi-dialect JSON Schema compiler (ADR 0007 still holds):
it consumes the same single Pydantic 2020-12 output, only without the Firestore
projection. It widens firepact's scope from "Firestore documents" to "the full
Pydantic -> TS surface a Firestore app needs", which is consistent with the
`pydantic2ts` drop-in promise (ADR 0003).

## Consequences

### Positive

- A project can remove `pydantic-to-typescript` and its hidden `json2ts` system
  dependency: Firestore docs via firepact, HTTP DTOs via `--plain`.
- Plain output is self-contained (Rust core, no Node).

### Negative

- firepact is no longer strictly Firestore-only; the plain renderer is a second
  emit path to maintain.

### Neutral

- A model used in BOTH a Firestore document (embedded) and an HTTP DTO is two
  genuinely different wire shapes (Timestamp vs string); plain mode and the
  Firestore path emit it in their respective files. Deduplicating context-
  independent shared types (enums) across the two layers is deferred (would need
  cross-file imports); the duplicate definitions are structurally identical and
  harmless.
